# 个人量化模型 V1 设计规格

- 状态：Reframed
- 日期：2026-07-13

> 方向修订（2026-07-13）：用户将主目标明确为“发现市场不同行业的变化与产业发展”。本规格中的多资产配置、持仓风险和 DeepVan 增强保留为下游行动层；上游研究主线改由 `2026-07-13-industry-change-radar-v1.md` 定义。

## 1. 决策摘要

本规格不追求预测每只股票的精确涨跌，也不尝试复制机构高频交易。它作为下游行动层回答：

> 在严格使用当时可见信息、计入交易成本并与简单基准比较后，DeepVan 事件信号是否能提高用户现有多资产组合的风险调整后收益？

模型形态固定为：

`低频多资产配置模型 + DeepVan 事件增强层`

DeepVan 只能作为一个另类数据特征源，不是标签、事实裁判或直接交易指令。真实交易继续由用户人工决定。

## 2. 第一性原理

一个系统只有同时满足以下条件，才可以称为量化模型：

1. 输入是带有明确可用时间的历史数据。
2. 输出对应一个事先定义的预测目标。
3. 参数由历史样本估计或由预先冻结的规则生成。
4. 结果能在未参与开发的样本外数据上复现。
5. 组合收益计入交易限制、滑点、费用和无法成交情形。
6. 任意历史决策都能按当时数据完整重放。

现有 `score_daily_action.py` 保留为启发式基准 B3，不作为 V1 的最终预测模型。

## 3. 目标与非目标

### 3.1 目标

- 对用户实际可投资的资产模块产生 1、5、20 个交易日的预期超额收益或排序分数。
- 单独估计未来风险，包括波动率、最大不利波动和相关性变化。
- 将预测转换为受仓位、集中度、换手和成本约束的目标权重。
- 定量识别 DeepVan 事件层相对纯市场模型的增量价值。
- 形成研究、回测、模拟盘、人工执行和复盘的闭环。

### 3.2 非目标

- 不做高频或日内统计套利。
- 不自动登录券商、提交订单或移动资金。
- 不用一百条左右的近期帖子直接训练高容量神经网络。
- 不把漂亮的历史收益曲线当作模型成立的充分条件。
- 不绕过知识星球权限或批量保存付费原文。

## 4. 投资范围与时间规则

### 4.1 两层标的体系

V1 将研究标的和真实执行标的分开：

- **研究标的**：有连续、可复权日频数据的指数、ETF 或其他流动性代理。
- **执行标的**：用户真实持有或可购买的场外基金、QDII、ETF 和少量 A 股。

每个执行标的必须映射到一个研究代理，并记录跟踪误差、币种、估值时差和交易限制。

### 4.2 初始资产模块

- `qd`：海外成长、纳斯达克、标普及新兴市场暴露。
- `quant`：A 股量化或宽基增强暴露。
- `defense`：现金、低波、公用事业、黄金或其他防守暴露。
- `a_share_alpha`：个股卫星仓，仅用于独立评估，未通过准入前不得由模型自动建议新增。

### 4.3 决策与成交时间

- 所有信号必须记录 `available_at`，即模型第一次合法可见的时间。
- 默认每日北京时间 20:00 生成研究决策。
- 回测成交使用各标的下一次合法成交机会，不允许使用信号产生前或尚不可得的收盘价。
- 场外基金按申购截止时间和未知净值规则处理；A 股按 T+1、涨跌停、停牌和最低费用规则处理。

## 5. 预测目标

### 5.1 收益标签

对研究标的 `i`、决策日 `t` 和期限 `h`：

```text
future_excess_return(i,t,h)
  = log(adjusted_price(i,t+h) / adjusted_price(i,t))
  - benchmark_return(t,t+h)
```

期限：`h ∈ {1, 5, 20}` 个交易日。

主目标为 5 日超额收益排序；1 日用于检查短期价格反应，20 日用于检查逻辑持续性。

### 5.2 风险标签

- 未来 5/20 日实现波动率。
- 未来 5/20 日最大不利波动（MAE）。
- 相对当前组合的边际风险贡献。
- 是否发生超过预设阈值的尾部损失。

收益预测和风险预测必须分开，不能用一个 0—100 分同时代表二者。

## 6. 时点数据契约

### 6.1 DeepVan 事件

标准事件至少包含：

```json
{
  "event_id": "stable-id",
  "source": "deepvan",
  "source_id": "topic-id-if-visible",
  "published_at": "2026-07-03T09:21:00+08:00",
  "captured_at": "2026-07-03T09:25:00+08:00",
  "available_at": "2026-07-03T09:25:00+08:00",
  "content_hash": "sha256",
  "event_type": "explicit_rebalance",
  "mentioned_instruments": [],
  "asset_buckets": ["qd"],
  "direction": "rotate_from",
  "horizon": "days",
  "source_clarity": 4,
  "novelty": 3,
  "catalyst": "",
  "invalidation": "",
  "summary": "非逐字摘要",
  "labeler_version": "event-labeler-v1",
  "human_reviewed": false
}
```

`event_type` 初始枚举：

- `explicit_rebalance`
- `risk_warning`
- `research_lead`
- `portfolio_discipline`
- `earnings_or_capex_catalyst`
- `emotion_or_joke`
- `postmortem`

必须把“原文可观察事实”和“模型解释字段”分开保存。修改标签不得覆盖原记录，只能生成新版本。

### 6.2 市场数据

每条行情必须包含：

- `instrument_id`
- `trade_date`
- 未复权与复权 OHLCV
- 复权因子及其当时可得版本
- 基准、币种和汇率
- 基金净值、估值日期、申购状态和溢价率（适用时）
- 停牌、涨跌停、上市和退市状态
- 数据来源、抓取时间和版本哈希

### 6.3 持仓快照

每次真实持仓变化后保存不可变快照：

- 数量、成本、权重、现金和币种。
- 可卖日期、申购赎回限制和单笔最低费用。
- 快照对应的 `as_of` 时间。

Obsidian 的 `当前持仓.md` 是人类可读视图，不是模型的唯一数据源。

## 7. 特征体系

### 7.1 市场特征

- 5/20/60 日动量和相对强弱。
- 实现波动率、下行波动率和近期回撤。
- 成交量、流动性和市场宽度。
- 估值、实际利率、汇率和 QDII 溢价。
- 资产间滚动相关性及风险集中度。

### 7.2 DeepVan 事件特征

- 事件类型、方向、清晰度、时效和新颖度。
- 与上一条同类观点相比是否发生立场变化。
- 同一主题在不同窗口内的重复强度和衰减值。
- 是否给出具体催化剂、仓位、期限和反证条件。
- 事件发生前相关资产已经上涨或下跌多少，用于识别追涨和反向因果。

### 7.3 组合状态特征

- 当前权重相对目标区间的位置。
- 组合波动率、回撤、集中度和边际风险贡献。
- 调整后的预计换手和成本。

任何特征只能使用 `available_at <= decision_time` 的数据。

## 8. 研究与模型阶梯

### 8.1 先做事件研究

在训练机器学习模型前，先回答：

- 各类帖子发布后 1/5/20 日的平均和中位超额收益是多少？
- 收益是否只来自事件发生前已经启动的行情？
- 控制市场趋势、波动和估值后，事件是否仍有增量解释力？
- 调仓、风险提示、研究线索和情绪表达是否存在显著差异？
- 结果是否由少数事件或单一行情阶段贡献？

样本不足数百个相对独立事件时，只做事件研究、收缩估计和低自由度模型，不启用高容量文本模型。

### 8.2 冻结基准

- `B0`：维持当前持仓，不调仓。
- `B1`：按固定目标区间定期再平衡。
- `B2`：趋势 + 逆波动的纯市场模型。
- `B3`：现有启发式评分脚本。
- `B4`：不包含 DeepVan 特征的市场预测模型。
- `M1`：市场特征 + DeepVan 事件特征。

只有 `M1 - B4` 的样本外增量稳定为正，才能声称 DeepVan 层具有 Alpha。

### 8.3 模型顺序

1. 事件条件均值和贝叶斯收缩。
2. Ridge / Logistic 回归。
3. 横截面排序模型。
4. LightGBM。
5. 只有在样本规模和基准结果支持时，才考虑文本嵌入或时序深度模型。

模型复杂度每提升一级，必须通过消融实验说明新增复杂度带来的样本外价值。

## 9. 风险模型与组合构建

### 9.1 独立风险模型

- 使用滚动协方差或收缩协方差估计资产风险。
- 监控海外成长、A 股、利率、汇率、商品和防守因子暴露。
- 输出组合波动率、预期最大回撤、集中度和压力情景损失。

### 9.2 组合目标

```text
最大化：预期超额收益 - 风险惩罚 - 换手成本 - 集中度惩罚
```

约束至少包括：

- 只做多、不使用杠杆。
- 资产模块上下限。
- 单只个股、单一主题和单一市场上限。
- 每期最大换手和最小有效调仓幅度。
- 低置信度事件不能单独触发新增风险。
- 无反证条件的个股事件不得进入可交易组合。

## 10. 回测协议

### 10.1 防泄漏

- 使用滚动或扩展窗口的 Walk-forward 测试。
- 训练集与测试集之间按最长标签期限执行 purge 和 embargo。
- 股票池、复权、财务数据和基金状态必须是 Point-in-Time 版本。
- 历史股票池和基金池必须保留当时成分及后来退市、清盘标的，禁止用今天的存活名单回测过去。
- LLM 标签器、Prompt 和模型版本在每个回测实验开始前冻结。
- 事件标签器不得读取未来收益、后续帖子或测试窗口统计结果。
- 禁止用测试集表现反复修改事件标签。
- 开始实验前预注册主目标、期限、特征集合、基准和准入阈值；新增假设必须登记为新实验。

### 10.2 成交与成本

至少模拟：

- 佣金、印花税、最低收费和滑点。
- 涨跌停、停牌、T+1 和成交量限制。
- 场外基金截止时间、未知净值、赎回费和到账延迟。
- QDII 申购限制、净值时差、汇率和溢价。

所有结果同时报告无成本与成本后版本，并做 1 倍、2 倍成本压力测试。

### 10.3 指标

信号指标：

- IC、Rank IC、ICIR。
- 方向命中率与概率校准。
- 不同期限、事件类型和市场状态下的稳定性。

组合指标：

- 成本后年化收益和相对基准超额收益。
- Sharpe、Information Ratio、最大回撤和 Calmar。
- 换手率、胜率、盈亏比和尾部损失。
- 单个事件、单一标的和单一时期的收益贡献度。

### 10.4 实验治理

每次研究必须生成不可变实验清单，至少记录：

- `experiment_id`
- 研究假设和预注册时间
- 数据快照哈希和样本时间范围
- 标签、特征、模型、费用和组合配置
- 代码版本、依赖版本、随机种子和运行时间
- 所有成功与失败的试验结果，禁止只保留最好结果

重复尝试不同特征、期限和参数时，必须报告试验总数，并使用多重检验修正、Deflated Sharpe Ratio 或等价稳健性方法。重叠期限标签需要使用适当的稳健标准误或分块 Bootstrap，不得把高度重叠样本当作独立观测。

## 11. V1 准入门槛

研究模型进入模拟盘前必须同时满足：

1. 至少四个相互隔离的样本外测试窗口。
2. 主目标的平均样本外 Rank IC 为正。
3. `M1` 相对 `B4` 的增量在多数测试窗口为正。
4. 成本后结果优于 `B0`、`B1` 中至少一个可执行基准。
5. 两倍成本下 DeepVan 增强层的增量结果不为显著负值。
6. 没有单个事件贡献超过整体利润的 20%。
7. 所有历史决策都能由数据哈希、配置、代码版本和随机种子重放。

模拟盘至少运行三个月或积累 30 个可交易事件，以较晚者为准。未通过前，输出只能标记为“研究建议”。

## 12. 对抗式审查

### 12.1 主要伪 Alpha 来源

- **反向因果**：作者在价格上涨后发帖，帖子只是行情结果。
- **选择偏差**：只采到仍可见或容易识别的帖子。
- **时间泄漏**：使用后来修改的帖子、复权因子或财务数据。
- **重复计数**：同一逻辑的连续帖子被当成多个独立信号。
- **市场状态混淆**：AI、QD 或资源品收益本来由大盘趋势驱动。
- **规则过拟合**：看到结果后不断调整强度、阈值和资产映射。
- **执行错位**：研究代理上涨，但真实基金因时差、限购或溢价无法获得同样收益。

### 12.2 强制反证实验

- 随机打乱事件日期后，策略表现应消失。
- 把事件整体延后一个或多个交易日，检查是否只是追随已有价格趋势。
- 去掉表现最好的 5% 事件后重新计算结果。
- 分别测试只用市场特征和只用事件特征。
- 在上涨、下跌、高波动和低波动阶段分别报告结果。

## 13. 与现有项目的集成边界

现有组件继续承担：

- `agent/deepvan_visible_text.py`：可见文本适配，但不再负责最终资产语义判断。
- `agent/deepvan_capture.py`：原始记录和去重。
- `agent/deepvan_daily_pipeline.py`：未来作为编排入口。
- `skills/deepvan-daily-action/scripts/score_daily_action.py`：基准 B3。
- `obsidian-vault/`：人类阅读、执行记录和复盘界面。

后续实现预计新增：

```text
configs/                 标的池、基准、费用与研究策略
data/events/             版本化事件数据
data/market/             Point-in-Time 市场数据
data/portfolio/          不可变持仓快照
research/                事件研究和基准实验
models/                  预测与风险模型
backtests/               回测配置、结果和实验清单
```

在实施阶段，不替换现有可运行流水线，而是先把它登记为基准，再逐层增加可验证模块。

## 14. 实施顺序

1. 确认真实执行标的、研究代理、基准和交易规则。
2. 建立市场数据与不可变持仓快照。
3. 将已有 DeepVan 索引转换为版本化事件数据并人工抽查。
4. 完成事件研究，识别可保留与应淘汰的事件类型。
5. 实现 B0—B4 基准和统一成本后回测。
6. 训练第一个低自由度 M1 模型。
7. 加入独立风险模型和组合约束。
8. 通过准入门槛后进入模拟盘。
9. 模拟盘稳定后，再决定是否增加定时采集和更复杂模型。

## 15. V1 完成定义

V1 完成不以“模型能输出分数”为标准，而以以下结果为标准：

- 任意历史日期都能还原当时可用数据和模型输出。
- DeepVan 层的增量价值能与纯市场模型独立比较。
- 所有报告均包含成本、风险、基准和反证实验。
- 模拟盘预测在生成后不可回改，并能与真实结果持续对账。
- 模型失败时能明确说明是数据、信号、组合、成本还是市场状态导致。
