# 宏观—行业—个股研报审计与三层量化因子 V1

- 状态：V1 代码框架已实现并以失败关闭方式运行；正式结果待真实数据验收
- 日期：2026-08-04
- 使用边界：个人研究；不连接自动下单

## 1. 决策目标

系统分别回答三个问题，禁止用静态加权总分掩盖冲突：

```text
宏观：当前能承担多少风险
  ↓
行业：风险和盈利更可能流向哪里
  ↓
个股：行业内部哪些公司更可能取得超额收益
```

第一项产出是可复核的历史能力审计：券商、分析师或团队在哪个维度、预测类型、期限和市场状态下有兑现记录。第二项产出是三层报告因子及两个预注册交互项。历史准确率和当前深读优先级是两张不同的榜。

## 2. 样本边界与免责声明

默认研报窗口为 `2024-07-01—2025-06-30`，评估截止 `2026-08-04`；因子研究历史窗口为 `2019-01-01—2025-06-30`。默认数据来自东方财富可公开抓取的页面、摘要、结构化字段及允许访问的 PDF，因此所有覆盖率必须标记为：

> 东方财富公开抓取样本，不代表券商全部报告。

未抓到不等于券商未发布，公开样本中的准确率也不能外推为券商全部研究能力。报告原文不打包传播。所有结果仅供个人研究，不构成投资建议，不产生订单，也不授予任何真实交易权限。

## 3. 点时契约和评分边界

- 每条研报、预测、真值和行情均保存 `available_at`；晚于决策时点的数据拒绝进入当期计算。
- 只有日期的历史研报，执行时点为真实交易所日历中的下一交易日开盘；未配置交易所日历时只保留覆盖记录，不进入正式评分。
- 宏观真值采用官方首次公布值；修订值只进附表。
- 基本面命中与市场收益有效性分列，禁止用其中一个替代另一个。
- 没有明确变量、方向和期限的“长期向好”“政策支持”标记为不可评分。
- 同报告的同主题同期限只保留一条；行业周报、重复维持评级和相似策略报告按 episode 去重。
- 只有到期预测才可更新后续技能；当前报告不能用自己的未来结果加权自身。

## 4. 类型与持久化接口

核心记录为 `ResearchReport`、`ResearchClaim`、`ClaimOutcome`、`SkillSnapshot`、`FactorObservation` 和带可用时间的日行情。SQLite schema v15 通过 `AuditStore` 管理；研报、行情、HTTP 响应和评价结果均保留不可变版本，可按决策时点回放。HTTP 响应和 PDF 由内容缓存管理；结构化预测绑定源记录哈希，正文预测绑定 `PDF SHA256 + 抽取器 bundle SHA256 + 抽取器版本 + 解析器版本 + Prompt 版本`。同一 `claim_id` 的异载荷会失败关闭，旧版本预测可诊断读取，但不能借用新版本验收结果进入评分。

编排层只依赖以下窄接口，避免把分析实现细节写死在 CLI：

- 采集：`EastmoneySource`、`CachedHttpClient`、`HttpCache`。
- 存储：`AuditStore.iter_*` 与 `AuditStore.upsert_*`。
- 抽取：`RuleBasedExtractor.extract`。
- 分析：`deduplicate_reports`、`evaluate_claims`、`build_skill_snapshots`、`build_factor_observations`、`rank_deep_reads`。

适配器只向函数传入其签名声明的参数。某层缺失或数据不足时，流水线继续生成覆盖率、异常和 manifest，但不得自行补值、模拟命中、生成券商排名或声称模型通过。

## 5. CLI

```powershell
python -m research.broker_report_audit audit `
  --dimensions macro,industry,stock `
  --as-of 2026-08-04 `
  --truth-input data/input/official_truth.jsonl

python -m research.broker_report_audit build-factor `
  --as-of 2026-08-04 `
  --trading-calendar data/input/exchange_calendar.csv

python -m research.broker_report_audit deep-read `
  --as-of 2026-08-04 `
  --limit 20

python -m research.broker_report_audit audit --offline `
  --dimensions macro,industry,stock `
  --as-of 2026-08-04
```

三个命令均支持 `--config`、`--db`、`--cache-dir` 和 `--output-dir`。`audit` 额外支持可重复的 `--truth-input`，可保存本地 JSON/JSONL/CSV 的首次发布值及修订值，但本地清单只能证明文件字节完整，不能证明其确为官方 URL 响应，因此一律仅作诊断；修订值始终不参与评分。`build-factor` 支持 `--trading-calendar` 和 `--factor-input`，但外部因子/标签文件仅用于诊断。默认值分别来自 `configs/broker_report_audit.v1.json`：数据库位于 `data/research_reports`，缓存位于 `data/cache`，报告位于 `data/reports/broker_report_audit`。`--offline` 严禁网络访问；空库不是程序错误，必须产出一套显式为空且不可评分的报告。

## 6. 能力估计

能力立方体为：

```text
券商/分析师/团队
× 宏观/行业/个股
× 预测类型
× 预测期限
× 行业或市场状态
```

只使用已成熟结果，最长回看五年，基础半衰期 730 天，并用 365 天做敏感性检验。小样本向团队、券商和全市场均值做经验贝叶斯收缩；一致跟风观点进行相关性折扣。分析师记录随本人，券商流程能力绑定报告发布时实体。榜单使用保守可信下界；有效样本不足配置阈值时只展示覆盖，不生成名次。

涉及券商合并或更名时采用点时实体。配置列出 18 个常见券商别名族：中信、中信建投、华泰、中金、国泰君安、海通、广发、招商、申万宏源、国信、中国银河、兴业、国金、东吴、浙商、天风、光大和国联（含国联民生别名）。别名归一化不能覆盖报告中的发布时实体；像“国泰海通”这类可能跨越两个历史实体的名称不得静默映射，必须进入异常表人工确认。

## 7. 因子与样本外准入

三组报告因子彼此独立，并与宏观、行业、个股客观因子分列保存：

```text
macro_report_factor
industry_report_factor
stock_report_factor
```

只允许 `宏观 × 行业` 和 `行业 × 个股` 两个交互项，不允许三阶交互。预测主目标是未来 20 个交易日个股相对所属行业超额收益，60 日为辅助。

比较四个冻结模型：`B0`（无研报）、`B1`（研报不按技能加权）、`B2`（仅个股研报技能）和 `M1`（三层技能及两个交互）。采用 36 个月训练、6 个月验证、6 个月测试的 Walk-forward，最终 12 个月冻结样本外，purge/embargo 为 120 个交易日，模型限 Ridge/Logistic。

只有至少四个样本外窗口中平均 Rank IC 为正、至少三个窗口相对基准增量为正、成本后分组收益不由单一行业贡献，`M1` 才具备进入模拟研究层的统计条件。当前 V1 尚无可为交易日历、客观因子、行业映射和内部标签签发正式证据的受控适配器，因此公共 evaluator 与报告器都固定失败关闭为 `not_admitted`；不能仅凭调用方布尔值解锁。

## 8. 深读队列

深读排序为确定性的字典序，不合成虚假的精确总分：

1. 对当前行业或个股排序的决策敏感度。
2. 与客观数据或其他高技能来源的冲突程度。
3. 相对上一份报告是否改变评级、目标价、EPS 或核心判断。
4. 来源技能的保守下界。
5. 是否明确、可证伪且包含期限和风险条件。
6. 原文证据和数据是否完整。

每项必须解释“为什么值得读”以及“读完可能改变哪个判断”。默认和硬上限均为 20；大模型异常模式默认关闭，即使人工开启也不得超过 20 份。

## 9. 固定产物与失败关闭

每次运行均生成：

```text
macro_accuracy.csv
industry_accuracy.csv
stock_accuracy.csv
broker_skill_cube.csv
three_layer_factor.csv
factor_walk_forward_report.md
three_layer_dashboard.md
deep_read_queue.md
source_coverage.csv
exceptions.csv
run_manifest.json
```

CSV 即使没有记录也保留固定表头。Dashboard 固定展示宏观环境、行业机会、行业内个股、三层冲突和深读清单；证据不足时对应项显示“未知/不可判断”。`source_coverage.csv` 记录每个维度的报告、可评分预测、成熟结果、排除原因和来源范围；`exceptions.csv` 保留行情冲突、行业映射失败、空泛预测、未成熟预测和口径差异。

`run_manifest.json` 记录命令、配置哈希、数据快照哈希、参数和每个产物哈希。离线重跑的研究内容和哈希必须确定；不得把运行时钟、随机排序或绝对机器路径写入决定研究结果的字段。

## 10. 验收门槛

- 三个维度各随机抽查至少 30 份报告，元数据与原页面 100% 一致。
- 自动抽取变量、方向、数值和期限的精确率至少 95%；未通过的抽取器不能进入正式评分。
- 三张维度准确率表永久独立，综合因子不得回写或修改原始评价。
- 离线重跑产物哈希一致。
- 所有排除和未成熟记录可追溯到报告或预测 ID。
- 未通过 Walk-forward 准入时，审计表与深读清单仍可用，但因子状态保持 `not_admitted`。

## 11. 当前实现边界

代码已经实现采集适配、版本化缓存与存储、规则抽取、真值导入、基本面/市场分离评价、能力收缩、三层因子、内部标签重算、Walk-forward、深读队列和固定产物。以下工作仍是正式研究结果的前置条件，不能用单元测试代替：

- 完成 `2019-01-01—2025-06-30` 研报、点时行业映射、行情和官方首次发布真值的历史回填。
- 提供真实交易所交易日历；工作日近似永远不能进入正式评分。
- 建立受控、带源响应哈希的交易日历、官方真值、行业映射与客观因子适配器；普通本地文件或调用方布尔值不能自证。
- 建立三个维度各 30 份、合计 90 份的逐条人工验证 manifest，并达到元数据 100% 和字段精确率至少 95%。
- 对随机样本逐条复核原页面、PDF、抽取证据和排除原因。
- 运行全部滚动窗口与最终冻结 12 个月测试，并实现 store-backed admission verifier；在此之前 `M1` 必须保持 `not_admitted`。
- 当前威胁模型假设本地 SQLite、内容缓存和 Python 进程未被恶意篡改；SHA256 用于完整性与重放，不是第三方数字签名。若要对抗本地注库或调用者伪造来源字段，还需签名采集日志或独立只读证据仓。

V1 当前只提供严格的本地官方真值导入契约，尚未把国家统计局、人民银行、巨潮和行业协会的每一种首次发布页面都实现成自动采集适配器。缺少这些真值不会被替代或猜测，而会明确进入异常与覆盖报告。
