# 华泰官方只读 API 接入边界与开通手册

- 日期：2026-07-14
- 当前状态：`blocked_pending_client_authorization`
- 已完成边界：只读本地快照契约与接入准备；策略所有权转换仍硬锁
- 未完成边界：尚未获得可验证的官方客户端、SDK 与账户授权，因此不能声称已经连接华泰

## 1. 结论先行

当前不能把华泰证券手机 App 当成一个公开 REST API 直接连接。公开资料支持的正规路线是华泰授权的 MATIC、MAPIs 或 MQuant；其中 MQuant 运行在 MATIC 客户端内部，适合先做“官方运行时读取账户 -> 本地文件快照 -> 本项目只读校验”的 Shadow 接入。

本项目只准备这个只读路径，不使用抓包、逆向 App、模拟点击交易或非官方登录接口，也不会在尚未开通权限时伪造一个“已接通”状态。LIVE 和真实委托永久不支持。

## 2. 第一性原理与对抗式审查

只读券商 API 接入至少要同时证明：

1. 接入通道由券商正式提供且该账户已被授权；
2. 账户绑定没有歧义，且不通过泄露账户号来识别；
3. 资金、持仓、委托和成交来自同一完整、足够新的快照；
4. 重启、断线和回报乱序不会把不完整快照标成完整；
5. 导出器、配置和快照都明确声明 `read_only=true`、`orders_enabled=false`；
6. 任一来源、账户、完整性或时效检查失败时都停止读取下游结果。

缺少任何一项，都只能保持 `blocked`；即使全部满足，也只获得只读 Shadow，不产生交易权限。

## 3. 官方公开资料能确认什么

华泰 [MATIC 官方页面](https://matic.htsc.com.cn/usercenter/login) 公开介绍了三类能力：

- MATIC：专业程序化平台，支持策略编写、后台执行、行情及回测等能力；
- MAPIs：面向获授权用户的统一 API，公开页面说明其开发包内包含 API Demo 和使用手册；
- MQuant：运行在 MATIC 客户端内的轻量脚本能力，支持 Python/C++、行情、回测、账户和交易相关函数。

公开网页没有给出一个可供任意个人账户直接申请密钥并从外部调用的 REST/OAuth 契约，也没有确认约 1 万元个人普通账户一定能开通。只读资格、费用和仿真权限必须由华泰 95597 或客户经理对具体账户确认。

华泰公开的 [《MATIC-MQuant 使用手册 V3.1》](https://s3.cn-north-1.amazonaws.com.cn/htscweb/huatech/attachment/MATIC-MQuant%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8CV3.1.pdf) 标注版本日期为 2021-01-27。该手册可用来理解架构与旧版函数，不可当作 2026 年当前生产契约。手册中的 Windows、内置 Python 3.6.2、客户端每日重启或登录时限、仿真环境等描述均须在拿到当前客户端和当前开发包后重新核验。

旧手册还揭示了几项会直接影响接入设计的约束：

- MQuant 策略运行环境不允许通过网络、socket 或 pipe 对外通信；
- 运行期读取文件受到限制，而写本地报告文件是支持的；
- 资金和持仓更新可能有短暂延迟，订单状态回报可能乱序；
- 平台前端不应被假设为一定替用户完成资金、持仓或业务规则预检查。

因此，先输出带完整性校验的本地只读快照，比臆造一个外部 HTTP 连接更符合官方运行方式和风险边界。

## 4. 本机检查结论

截至 2026-07-14，本轮只读盘点没有在当前项目或常见安装位置发现可验证的华泰 MATIC/MQuant 客户端、`MQuant_api.py`、`MQuant_struct.py` 或 MAPIs 官方开发包。因此现在无法执行一次真实账户只读探测。

这个结论只表示“当前检查范围内没有可验证安装”，不证明电脑任意目录一定不存在相关文件。拿到华泰授权下载入口后，应从官方渠道安装，并以开发包的版本、数字签名或哈希和实际函数签名为准。

## 5. 当前只读接入结构

```text
华泰正式授权
  -> 用户在本机 MATIC/MQuant 手动登录
  -> MQuant Shadow 导出器仅调用查询函数
  -> 原子写入 htsc-mquant-shadow/1 JSON
  -> Schema + payload_sha256 + 时效 + 随机绑定 ID + 实际账户 HMAC 指纹匹配
  -> 本项目只读展示；未通过所有权审计时固定禁止转换为策略持仓
  -> 不提交、不撤销任何真实委托
```

快照契约位于 `schemas/htsc_mquant_shadow.v1.json`，配置示例位于 `configs/htsc_mquant_shadow.example.json`。契约要求：

- `capabilities.read_only` 必须为 `true`；
- `capabilities.orders_enabled` 必须为 `false`；
- 资金金额、价格和成交金额使用十进制定点字符串，禁止二进制浮点和科学计数法；
- 数量使用整数；
- 资金、持仓、开放委托、当日委托和当日成交必须同时存在，空集合也要显式写为 `[]`；
- `capture.complete` 必须为 `true`；任一查询失败时不得输出“查询完整快照”；
- `capture.consistency` 固定为 `sequential_non_atomic`：五类查询顺序执行，不表示券商原子时点；
- 顶层 `payload_sha256` 用于发现截断、旧文件覆盖或被意外修改。
- `source.account_fingerprint` 是用仅留在 MQuant 运行参数中的随机秘密，对当前实际资金账号计算的 HMAC；切换登录账户后会变化，但原始账号不落盘。它只能检测诚实导出器的账户切换，不能认证快照来源。

`payload_sha256` 的唯一算法是：从完整对象中移除该字段，使用等价于 Python `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)` 的规范 JSON，UTF-8 编码后计算 SHA-256，再写成 `sha256:<64位小写十六进制>`。Schema 只能验证格式，适配器还必须重新计算并恒时比较内容。它是无密钥内容校验，只能发现截断或误改，不能证明文件一定来自华泰。当前适配器因此固定输出 `source_authenticated=false`，且持仓所有权转换硬锁；本仓库不会把该链路扩展为交易写接口。

## 6. 开通与落地清单

1. 用华泰官方客服电话 95597 或客户经理确认该个人普通账户可用的正规通道：MQuant、MATIC 或 MAPIs。
2. 逐项确认只读与仿真权限是否分离，是否有资产、设备、IP、证书或软件费用要求。
3. 索取当前官方客户端、当前 MQuant 帮助手册及 `MQuant_api.py` / `MQuant_struct.py`，或当前 MAPIs 开发包；拒绝网盘转载和来源不明的 SDK。
4. 用户本人在华泰官方客户端输入账号、交易密码、短信验证码和证书信息；这些信息不交给 Codex、不写配置、不截图保存。
5. 安装完成后，用 `inspect_local_sdk_shape.py` 静态检查 `MQuant_api.py` 与 `MQuant_struct.py`；得到的 `local-shape-sha256:<hash>` 只可作为本地形状/漂移标识，不能证明华泰来源、当前版本或运行时实际加载。必须另外核对官方下载来源、客户端版本并实测只读回包。
6. 在本机生成随机 `account_binding_id` 和至少 32 字符的 `account_binding_secret`。后者只输入 MQuant 运行参数，用于对实际资金账号计算 HMAC 指纹；原账号和秘密均不写入项目。
7. 首次运行只读取资金、持仓、开放委托、当日委托和成交；将屏幕数据与快照人工逐项对账。
8. 连续完成 Shadow 门禁和故障演练；Shadow 是本仓库券商接入的终点，不能把只读脚本原地改成下单脚本。

## 8. 隐私与凭据边界

以下内容不得进入 Git、配置、快照、日志、聊天或测试夹具：

- 资金账号、股东账号、身份证号、姓名、手机号；
- 登录密码、交易密码、通讯密码、短信验证码；
- 证书私钥、设备指纹、会话 Cookie、Token 或二维码；
- 含完整账户号的客户端截图和交割单原件。

用户只在华泰官方客户端本机界面完成登录和验证。本项目只保存随机本地 `account_binding_id`、不可逆 HMAC 指纹、业务数据和必要的时间戳；HMAC 秘密只留在 MQuant 运行参数中。快照目录应仅对当前 Windows 用户开放，日志只记录掩码后的标识。任何校验失败、实际账户指纹变化、数据过期、文件哈希不符或字段缺失都必须 fail closed。需要明确：HMAC 匹配和内容哈希都不认证快照生产进程。

## 9. Read-only -> Shadow 门禁

### Gate 0：Blocked

- 当前状态；官方客户端、SDK 或账户授权尚未验证；
- 配置必须保持 `status=blocked_pending_client_authorization`、`read_only=true`、`orders_enabled=false`；
- 任何委托或撤单调用均不可达。

### Gate 1：Read-only

- 当前官方开发包的函数与字段已在本机核验；
- 当前本地文件静态形状检查生成的 `local-shape-sha256:<hash>` 与导出器、配置完全一致；它仅用于漂移检测，不能单独通过官方来源/运行时门；
- 官方下载来源、客户端版本及实际加载/回包由人工确认；当前代码不能自动认证生产进程；
- 用户手工登录，导出器仅包含查询能力；
- 资金、持仓、开放委托、当日委托和成交均能完整读取；
- Schema、内容哈希、时区、交易日、快照年龄和随机账户绑定全部通过，同时接受其 `sequential_non_atomic` 限制；
- 连续人工对账无未解释差异。
- 这里只开放券商事实读取；持仓转成策略所有权的持久化审计账本尚未实现，因此仍禁止生成可执行策略账户。

### Gate 2：Shadow

- 模型生成“本应提交”的限价订单，但官方通道不收到任何委托；
- 按现有交易规格至少完成 5 个完整交易会话；
- 完成断线、客户端重启、重复快照、过期快照、回报乱序、部分成交、撤单中成交和未知订单恢复演练；
- 策略账本与用户长期持有的美的集团等非策略资产严格隔离。
- 必须先实现不可由调用方自报的所有权事件链，证明每一份策略持仓都来自本系统已确认成交；当前代码对此固定拒绝。

### LIVE（永久不支持）

Shadow 是本仓库券商接入的最高阶段。`ExecutionMode.LIVE` 只为兼容保留；任何配置、令牌、白名单、SDK readiness 或账户状态都不能解锁，统一返回或抛出 `live_not_supported`：`LIVE execution is not supported by this repository`。
